## Obliviousness (P3): what the branch-divergence result means

Generated by `python -m vcloak.bench.report_oblivious` from ingested run dirs; do not edit this block by hand.
The measurement itself is section 4.O.5 of `docs/REPORT_CH4_NOTES.md`.

**Result.** An instrument that read 128 divergent branch targets on a planted-leak control reported 0 on 3 of the 4 audited kernels (runner `pc-rtx3050laptopgpu`, NVIDIA GeForce RTX 3050 Laptop GPU).

**Why it is stated this way.** A profiler that reports 0 divergent branches proves nothing by itself: the counter
may be unsupported, refused or silently empty. Here the same counters, in the same `ncu` process, were first shown
to see a leak that was planted on purpose: 128 divergent branch targets beside
8704 uniform ones on `planted_leak` (`runs/20261014-003929_M08_ncu`, `control` of summary.json). The zeros
of the audited kernels are therefore a validated null, which is a categorically stronger statement than an
unvalidated one. It is still a null: it says no thread of a warp took a different branch target from its
neighbours in this run, not that none ever can.

**Kernels the statement covers** (runner `pc-rtx3050laptopgpu`):
- `bitonic_shared`: 0.0<!--M:T-NCU-DIVERGENT-BITONIC-SHARED--> divergent, 4480 uniform branch targets counted beside it (7 launch(es)).
- `bitonic_shared_full`: 0.0<!--M:T-NCU-DIVERGENT-BITONIC-SHARED-FULL--> divergent, 4096 uniform branch targets counted beside it (1 launch(es)).
- `aead_open_seq`: 0.0<!--M:T-NCU-DIVERGENT-AEAD-OPEN-SEQ--> divergent, 2560 uniform branch targets counted beside it (1 launch(es)).

**Kernels it does not cover:**
- `bitonic_pairs_global`: NOT_MEASURED<!--M:T-NCU-DIVERGENT-BITONIC-PAIRS-GLOBAL-->. The counter collected nothing: 0 uniform and 0 divergent targets, although the sm_75 listing of this kernel has 2 branch instructions (1 conditional).
A kernel is dropped rather than counted as a zero when its counters were empty and the SASS listing shows it has
branches: an empty counter is not a reading. The other kernels are kept because their own uniform count is
non-zero, which shows the counter was collecting for them.

**Where it was measured, and where it was not.** The cloud runner (`kaggle`, Tesla T4) refused the
GPU performance counters, so divergence is `NOT_MEASURED` on the Tesla T4 (ISSUE-18). Divergence was therefore
measured on a second platform, runner `pc-rtx3050laptopgpu` (NVIDIA GeForce RTX 3050 Laptop GPU, compute capability 8.6), with the
positive control (ISSUE-48). The two platforms are reported side by side and never pooled (ADR-024,
ADR-025): this divergence table is the only result of section 4.O that comes from the second platform, and
nothing from it replaces a Tesla T4 value.

**Limits.** One run, seed 8, log2n 16, one GPU model; the profiled code is the nvrtc build
for compute capability 8.6, not the code that ran on the Tesla T4. The values are sums of an `.avg`
aggregate whose exact definition was not checked, so they are read as zero / non-zero. Branch divergence is one
channel: this result says nothing about timing, where the dudect findings of section 4.O.3 stand as measured.
